# Context对照实验协议

本实验使用隔离源码副本，不修改运行时工作区或既有服务。先冻结本协议、输入生成器、源码及采集程序，再做方法预检和正式测量。失败轮次保留，修改采集方法后重新冻结，不能与前一方法混用。

## 固定矩阵

通信：三种操作，即产物发布、已加载读取、首次依赖补发；正文256、4096、32768字节；接收方1、4；并发1、4；每轮4次操作。每个配置各版本先预热1轮，再测量6轮，版本顺序遍历全部六种排列。共36个配置、648轮测量、2592个计时样本。读取每个样本重复32次，分析时除以32；吞吐量按整个计时窗口内完成的逻辑操作数计算，不使用单次延迟倒数。

压缩：英文与中英混合两类固定文本，256、2048个生成单元；分别使用whitespace-v1和unicode-segment-v1本地计数器。预算为实际源计数的1/8、1/2和全部；比较关闭压缩、禁用缓存命中、启用持久缓存。每组预热1轮、测量6轮；每轮包含首次读取、连续8次重复读取和一次重新打开持久仓库后的读取。共12个配置、216轮测量、2160个读取样本。重开仓库耗时单列，后续读取耗时不混入加载耗时；这不等同于机器冷启动或清空文件系统缓存。

固定事实标记位于生成单元的10%、50%、90%位置，完整输入和输出均保存。事实保留率只度量这些人工标记，不代表自然语言理解、业务回答质量、真实模型Token或API费用。当前截取器保留前缀；关闭压缩可能整页丢弃。预算满足与信息保留必须同时报告。

## 环境与测量

原计划使用同一openEuler虚拟机。预检及第一轮完整执行发现VirtualBox反复出现计时追赶失败，来宾系统记录时间前跳及系统服务看门狗超时，因此这些结果保留为功能和环境诊断记录，不能用于性能定论。入口新增Windows支持，平台数据独立保存，不混合汇总。Windows测量使用同一主机、同一Go版本及相同参数；这不替代openEuler性能验收。两个平台均固定GOMAXPROCS=2、GOMEMLIMIT=768MiB，构建串行。

测量时不并发执行其他实验或向目标环境传输证据，不改变服务、安全策略或系统缓存。固定随机种子20260922打乱配置顺序；每个配置内部平衡版本顺序。预检与正式数据分别保存。无人工暂停或删去慢样本，不预设显著性结论。

保存延迟、整体窗口、Go分配量和堆读数、检查点文件大小、成功保存次数与序列化字节数。分配量不是RSS或峰值内存，序列化写入字节不是物理磁盘写入。计时区间排除负载预置和显式GC；通信保留操作内部正文检查；压缩计时仅含Resolve，后验核查不计入。

正式运行前，对A、B、C的Context相关包执行并发检查。N执行与禁用缓存命中不冲突的提交失败、元数据拒绝和非法摘要测试；缓存命中次数由实验逐次核验。所有版本执行相同通信正文、重放和重载检查，并记录任务隔离结果。当前版本出现任何未预期错误则停止整轮实验；原版已知隔离差异作为结果保留。

## 复现

在仓库运行`python experiments/context-evaluation/prepare.py`，生成四个源码归档、源码清单、统一适配器及Linux入口。将生成目录复制到普通用户可写的openEuler目录；先执行`python3 run.py --pilot`做方法检查，再执行`python3 run.py`运行正式矩阵。预检标记不得作为正式测量汇总。

Windows可直接在生成目录运行`python run.py --build-only`完成构建与相关并发检查，再执行`python run.py --reuse-build <已验证构建目录>`复用同一二进制进行测量。复用前仍核对源码、二进制及测试记录身份，不重复运行没有变化的测试。运行目录及报告必须明确标记Windows平台。

首份Windows完整矩阵保留2160次单次压缩读取，其中1430条延迟为0。追加的计时协议使用`--compression-only --compression-read-passes 32`：首次读取和重开仓库后的读取仍为1次，八个重复读取样本各连续调用32次，再把计时和分配量除以32。完整补测仍为216轮、2160个计时记录，实际包含55728次读取。它与原始单次计时数据分开保存，不拼成同一分布，也不把32次调用当作32个独立计时样本。计时循环内核对重复正文不变，所有错误均中止该轮。

每次运行均创建新目录。源码清单逐项核对Git原版、当前副本、实验补丁和统一适配器；编译结果及逐轮结果绑定SHA256，结束时再次检查源码和二进制。原始检查点与人工标记核验由独立分析入口重新读取，不仅相信采集器的成功布尔值。
